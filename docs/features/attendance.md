# Attendance user flow

1. From the Attendance page, choose a course and session date, then select **Load roster**. The roster lists every student enrolled in the course (course names match regardless of case) and restores statuses already recorded for that session.
2. Choose Present, Absent, or Exempt beside each student. Changes save optimistically through the authenticated attendance API; a failed write restores the prior value and announces the error. (Attendance statuses are Present, Absent, and Exempt; the legacy Late status has been retired and Excused migrated to Exempt). Choosing the status a student already has clears the mark. Dates in the future (India time) are rejected.
3. **Mark all present** submits Present for each student. The unique `(student_id, course_id, session_date)` constraint and API upsert make repeat marking update the existing row instead of duplicating it.
4. Use arrow keys while focused on a status control to move across statuses or between students. The roster table features bounded scroll containers guaranteeing smooth responsiveness on mobile, laptop, and desktop viewports.

The Attendance route also lists paginated historical records, a course percentage report, and a per-student percentage report for the selected course. Percentages are computed by PostgreSQL views: Present and older Late marks count as attended, and Exempt sessions are left out (the same rule as the dashboard and reports). "Marked by" shows the name of whoever marked the record, for staff too. Enrollment is currently resolved through the student's course name; cohorts that need course IDs or batch-level enrollment need a schema decision. Reports show up to 100 course and student rows.
